# Implementation Planning

## Purpose
Create a bounded, reviewable plan before non-trivial work.

## Use when
- more than a trivial change is expected
- the task touches multiple files or systems
- validation will need coordination

## Procedure
1. Summarize the goal.
2. Minimize the expected change surface.
3. Break work into reversible steps.
4. Define validation after each major step.
5. Identify stop points for reassessment.

## Output
- plan
- files or systems likely affected
- validation steps
- stop conditions
